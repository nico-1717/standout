# STANDOUT — Architecture map (for AI sessions)

Read this first; open `docs/STANDOUT_PROGETTO.md` only for conventions detail, `docs/STANDOUT_PROGETTO_flashcard.md` for flashcards.

## 1. Tech stack & conventions
- PHP 8 procedural, MySQL/MariaDB (mysqli), vanilla JS + CSS. **No build step, no framework, no npm.**
- Every query goes through `lib/security_core.php` helpers: `sec_q`, `sec_one`, `sec_all`, `sec_in`, `sec_int`, `sec_enum`, `sec_h`; writes call `sec_guard_write` (rate limit); JSON via `sec_json`; CSRF via `sec_csrf_token()` + `X-CSRF-Token` header. Never concatenate SQL.
- Every row is scoped by `user_id`; check ownership in every query.
- CSP (set in `security_core.php`) blocks external script/style hosts: load nothing from CDNs; vendor files live in `public/_assets/`.
- **CSP has no `'unsafe-inline'` for scripts.** Never write `onclick="..."` (any `on*=` attribute) or a bare `<script>`/`<style>`: use `data-on-click="fn(args)"` (also `data-on-change`, `data-on-input`, `data-on-submit`, ...; run by `public/_assets/js/standout_events.js`, a tiny safe interpreter: calls, `this`, `event`, literals, `if`, `return`, few assignments - for anything more write a real function in a `.js` file) and `<script nonce="<?php echo sec_nonce(); ?>">`. `style=""` attributes are still allowed. `tools/audit_sicurezza.py` flags violations.
- i18n: all UI text in `lang/it.json` and `lang/en.json`, used via `t()`, `te()` (echo), `T()` (JS). Keep both files in sync.
- Comments are in Italian and explain *why*, not what. Do not rewrite working code; make minimal, targeted changes.
- Inside `function_exists` blocks use `define()`, not `const`.
- Schema changes: edit `sql/schema.sql` AND add `sql/migrations/YYYY-MM-DD_name.sql`.
- Offline-capable pages use an action queue (provisional ids, replay on reconnect): see planner and Pomodoro.
- Checks before commit: `php -l`, `node --check`, balanced CSS braces, `tools/controlla_colonne.py sql/schema.sql <php files>`, `tools/controlla_csp.py lib/security_core.php <php files>`.

- **Accounts**: `users(id, username, email, lang, ui_style)`, `roles(id, level)`, `user_roles(user_id, role_level)`, `remember_tokens(id, user_id)`, `api_sessions(id, user_id)` (one row per device of the app: only hashes of the two tokens; migration `2026-10-28_api_sessioni.sql`), `login_attempts(id)`, `rate_limits(id)`, `security_audit_log(id)`.
- **Billing/AI**: `plans(id)`, `user_plans(user_id, piano_id)`, `ai_credit_ledger(id, user_id, delta)`, `ai_job_steps(id, job_id, seq)`.
- **Planner**: `planner_events(id, user_id, title)`, `planner_calendars`, `planner_categories`, `planner_places`, `planner_priorities(id, user_id, priority_date)`, `planner_weeks(id, user_id, week_start)`, `planner_week_lists`/`_items`, `planner_routines`/`_items`, `planner_settings(user_id)`, `event_guests`, `contacts`.
- **Google sync**: `google_calendar_accounts(user_id)`, `google_calendar_map(id)`, `google_sync_queue(id)`, `google_sync_log(id)`.
- **To do**: `todos(id, user_id, list_type, parent_id, project_id, buy_category_id)` (list_type: todo|buy; the page no longer shows study), `todo_buy_categories(id, user_id)`, `todo_notes(user_id)`, `todo_buy_memory(user_id, chiave)` (what gets bought often).
- **Diary/habits**: `diary_list_items(id, user_id, entry_date)`, `diary_settings(user_id)`, `diary_ai_books(id, user_id)` (AI-written diary books), `diary_ai_reports(id, user_id; one per quarter)`, `habits(id, user_id; a future `start_date` keeps the habit out of the habits list until that day: it is in `future` of the habits bootstrap and behind the «See future habits» button)`, `habit_logs(id, habit_id, log_date)`, `habit_categories`, `habit_achievements`, `pill_plans(id)`, `pill_doses(id, plan_id)`.
- **Project plan**: `plan_goals(user_id, project_id)` (minutes, kind, priority, deadline per project), `plan_paint(user_id, project_id, day)` (highlighted days), `plan_days(user_id, day, project_id, kind)` (the scheduled minutes, source auto|manual), `plan_settings(user_id)`, `plan_templates(id, user_id)`. Created lazily by `piano_api.php`; migration `2026-10-26_piano.sql`.
- **Home**: `home_layout(user_id)` (JSON of widget ids + on/off, in order), `fc_quick_drafts(id, user_id)` (flashcards captured as front only, finished later into `fc_study_cards`). Created lazily by `home_api.php`; migration `2026-10-27_home.sql`.
- **Projects/Pomodoro**: `projects(id, user_id, parent_id)`, `pomodoro_sessions(id, user_id, start_time)`, `pomodoro_current_breaks(user_id)`, `pomodoro_settings(user_id)`.
- **Flashcards (study)**: `fc_study_decks(id, user_id)`, `fc_study_cards(id, category_id)`, `fc_study_subcards(id_child, parent_id)`, `fc_study_learnt(user_id, fc_image_id)`, `fc_study_plays`, `fc_study_records(user_id, kind)`, saved AI texts `fc_study_ai(card_id)` for parents and `fc_study_ai_child(child_id)` for children (explanation + metaphor; the child table is created lazily by `lib/fc/fc_ai_saved.php`, migration `2026-10-26_spiega_figli.sql`).
- **Vocabulary**: same shape with `fc_vocab_*` plus `fc_vocab_courses(id, user_id, known_lang, learn_lang)`; `fc_vocab_records(user_id, course_id, kind)`.
- **Shared flashcards**: `fc_games(id, kind, course_id)`, `fc_game_durations`, `fc_settings(user_id)`, `fc_goals(user_id)`.
- **Other**: `university_exams(id, user_id)`, `university_settings(user_id)`, `friends`, `friends_notifications(id)`, `study_templates(id)`, `push_subscriptions(id)`, `weather_cache`, `place_cache`.

## 3. File map
- `lib/` — shared PHP: `bootstrap.php` (the single entry point every page includes: it loads `config.php` = DB/keys/`PWA_BASE`, then language, PWA meta, Pomodoro bar; `tools/controlla_bootstrap.py` forbids including `config.php` directly), `config.php` (DB, secrets; gitignored), `security_core.php` (sec_* helpers), `auth_*.php` (session/login guard; `_api` variant returns JSON), `password_policy.php` (min 10 chars + common-password list), `email_verifica.php` (soft email verification), `fc/fc_files.php` (delete a media file only if no other card uses it), `i18n.php`, `stile.php` (UI style).
- `lib/fc/` — flashcard domain: `fc_type.php` (study vs vocabulary switch, URLs), `fc_ripresa.php` (where an unfinished game resumes, shared by Result, History, Home and the Flashcards page), `fc_impostazioni.php` (per-user game settings), `fc_vocab_gap.php` (example gap selection), `fc_ai_*.php` (AI prompts and formatting; `fc_ai_saved.php` tells which cards already have a saved Explain / Metaphor; `fc_frantuma.php` holds the pure helpers of Break up: card document to plain text, validation of the attachment assignments).
- `lib/planner/` — planner domain logic split by topic (events, places, categories, day view).
- `lang/` — Italian and English dictionaries.
- `sql/` — `schema.sql` plus dated `migrations/`.
- `tools/` — Python checkers (CSP, columns, smoke test).
- `public/api/v1/index.php` — the single front door of the app API (`.htaccess` sends every `/api/v1/*` here). Routes are one list at the bottom of the file; `lib/api_v1.php` does the common work (JSON `{ok, error, code}` answers, who is calling, CSRF only for cookie requests, `terms_required`); `lib/api_sessioni.php` holds all token logic (login, refresh rotation, revoke, prune). `standout_utente_corrente()` in `auth_core.php` checks the Bearer token (or `X-Standout-Token`) first, then the cookie. The password change (`public/account/cambia_password.php`, form on `privacy_dati.php`) calls `api_sessioni_revoca_tutte($uid, true)`; a future «forgot password» reset must too. `api_sessioni_revoca_tutte(…, true)` also raises `users.session_version` (migration `2026-10-28_session_version.sql`): each login stores the value in `$_SESSION['sv']` and `standout_utente_corrente()` drops a session whose number is older, so sessions already open in other browsers end too. Test client: `tools/prova_token.py`.
- `public/planner/` — planner, diary, habits, **to do / to buy** (`todo_widget.php` component; `todo_api.php` backend; `todo_barra.js` quick-add bar for to do; `todo_buy.js` + `todo_buy.css` to buy with two looks, Aisles (standard) and Receipt (paper); `todo_nota.js` + `todo_nota_ai.php` quick note and AI sorting), Google Calendar sync (`google_calendar.php`), `js/` planner scripts (`04_barra_e_priorita.js` holds the smart bar parser).
- `public/fc/` — flashcards: `fc_home.php` (hub: Study card, Languages card with one row per course, goal ring, "cards you know" split into Study and Languages (words) tiles that also filter the chart; Play on both cards goes to `fc_history.php`; styled by `fc_hub.css`), `fc_languages.js` (the add-language / course-options / delete sheets that live inside `fc_home.php`) and `fc_languages.php` (no longer a page: only the POST handlers for those sheets — add, variant, project, delete, order — and a redirect to `fc_home.php`), `fc_decks.php` + `fc_decks.css` (the categories/decks list, `?course=N` for a language course; the "to review" count is a dark badge on the deck icon, `.cs-badge-rip`, built by `fcm_badge_ripasso()`; the numbers row is `fcm_riga_html()`), `fc_result.php` (game summary; each card and the card viewer have a pencil to `fc_card_edit.php?…&return_to_result=1&game_id=N`, which returns to the summary), `fc_history.php` (game history; the Play button of a language row goes here), `fc_stats.php` (study statistics), `fc_game.php` (the game page; study cards use the same veiled answer slot as vocabulary, `.fcv-slot` / `.fcv-ans`, with the study-only bits `.fcs-*`: examples inside the answer, a small «Add example» button only when there are none (updated through `fcOnExamplesCount`, called by `exScriviChip` in `fc_examples_modal.php`), Explain / Metaphor chips that show «Saved»; no emoji in the UI; its header is a path, not bars: the server writes a raw model in `.f2-dati`, `f2Disegna()` draws one disc per checkpoint stretch with its error count, a double ring next to the counter (concepts / cards to the next checkpoint) and tints everything with the colour of the current card's category, tweening it in OKLCH on page swap; the checkpoint step comes from localStorage `fcv_checkpoint`, shared with `fc_game_juice.js`; tapping a disc opens `#erroriElenco` filtered to that stretch; `.f2-ritorno` is a small arrow under the path, drawn only when the current card is not the first one still to answer, and takes you back to it; in a replay of mistakes (`fc_games.parent_id > 0`) `scorriAlPrimoDaFare()` scrolls straight to the first child still to answer, the father stays above, already marked right), `fc_game_start.php` (creates a game), `fc_voice_mode.php/.css` (hands-free voice mode: commands and their synonyms come from `fc.cmd_*` in the lang files; the mic is restarted after every session even while the native voice reads or is paused, `micPuoRiavviarsi()`), `fc_speak.js` (text-to-speech helper), `fc_settings_api.php` (game/voice settings).
- `public/fc/fc_insert.php` (+ `fc_insert.css`, `fc_insert_card.*`, `fc_insert_save.php`) — the big insert/edit page for cards, study and vocabulary (the edit mode reuses it). The header is `position:fixed` in `fc_insert.css`: any stylesheet linked later from the body (`fc_ai_panel.php` adds `ai/credits.css`) must scope its `.app-header` rules, or it overrides the fixed header (this happened). Row status is `new|clean|edited|deleted`; a saved row is removed with `deleteRowSoft()` (a stub the server deletes on save), never just taken out of the DOM. A word row has several quick examples (`.fcv-exq-item`, `fcvEsempioHTML()`, cleanup after a save in `fcvEsempiSalvati()`), sent as `cards[i][examples][k][text|gap]` and written by `fc_esempio_rapido()` in `fc_insert_save.php`, which returns the card's total example count (the old single `example`/`example_gap` is still accepted, for a tab left open from before the deploy).
- `public/fc/fc_ai_panel.php` + `.js`, `fc_smart_import.js`, `fc_ai_match.js` — the AI / import / images panel of the insert page. «Create the cards» (paste import and images) REPLACES the cards in the table: `svuotaTabella()` soft-deletes saved rows and asks for confirmation only when something would be lost. «Generate with AI» (languages, `generaParole()` in `fc_smart_import.js`) appends instead.
- "Cards you know" (home, stats): one function, `fcv_conosciute()` in `lib/fc/fc_vocab_gioco.php` — marked learnt, or level la_sai, **or inside an archived deck/branch** (archived cards have no date, so they count in totals but not in the per-day chart).
- Card levels (new, seems easy, easy, tricky, hard...): rules explained in `docs/flashcard_levels.md`, code in the header comment of `lib/fc/fc_vocab_gioco.php` (`fcv_livello_prefisso`), twin in `livello()` of `public/fc/fc_game_juice.js` — change both together. - `public/projects/` — projects tree and Pomodoro (`pomodoro_core.js` engine, `pomodoro_stato.php` state, `pomodoro_barra.*` global bar). - `public/projects/piano_api.php`, `piano.js`, `piano.css` — the project planner (replaces the old «to study» calendar). Unit is the minute. Views: inside a project **List | Calendar | Plan** (switch in `progetti.php`, `#ppViews`/`#ppHost`), and in «Projects → Calendar» (`?view=cal`, `#ppMaster`) **Today | Calendar | Overview**. API actions: `tree`, `goal_save`, `split_save`, `paint`, `day_set`, `autoplan` (preview/apply), `master`, `today`, `skip_fix`, `settings_*`, `import_old`, `tpl_*`. Planner (`pn_pianifica`): each unit (a project with minutes and no budgeted child) gets, each day, remaining ÷ usable days; a full day is shared by weight must 3 / should 2 / nice 1 with water-filling; units below the minimum block accumulate and run every other day; when total need > 60% of total free time spare time is used to work ahead. Free time per day = measured pace (pomodoro days of the last 60) or the user's value, minus timed planner events, 0 on the rest day. Highlighted days restrict a unit (or its sub-projects) to those days. Manual blocks (`source='manual'`) are never overwritten by autoplan.
- `public/ai/` — AI endpoints and the credit/job system (`ai_job_api.php`, `ai_worker.php`, `credits.php`). Study game tools: `ai_generate_text.php` (Explain / Metaphor; the text is saved on the card the first time and read back for free afterwards, `cached` in the response, `is_child` picks the table), `ai_tutor.php` (audio, cached on disk by text), `ai_shatter.php` (Break up: uses only the card's own text, may answer `split:false`, drops cards whose `src` quote is not in the original) and `ai_shatter_save.php` (saves the result as a title parent card with children; «keep» leaves the original alone and puts the family right after it; «replace» turns an original parent into the title card in place (same row, so game history, learnt and favourites stay) or deletes an original child and creates the family after its parent. To-buy shows only items with a date <= today, else priority 1, else the first item. Offline: `sw.js` keeps a copy of the logged-in Home page (index.php sends `X-Standout-Shell: home`; deleted on logout or when Home answers logged-out) and the `?v=` static files, so the Home opens without network from the localStorage copy; coming back online after an offline start reloads the page. The last response is saved in localStorage (per user id) and painted instantly on the next open, then only widgets whose data changed are redrawn; first visit shows skeletons plus the thin `#hoLoad` bar. Ticks go to the existing todo/habits/planner endpoints. The avatar popup (`partials/notifiche_widget.php`) also holds the AI usage bars (`home_api.php?ajax=ai_usage`).
